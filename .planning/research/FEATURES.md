# Feature Research

**Domain:** 아동 줄넘기 수업용 블루마블식 순환판 3D 보드게임 (강사 1명·기기 1대, 2~8 플레이어/팀, 20~40분 수업)
**Researched:** 2026-10-22
**Confidence:** MEDIUM — 장르 관행(Monopoly Junior, Mario Party, 부루마불)은 공개 규칙·위키로 교차 확인했다(MEDIUM). 아동 연출 타이밍과 체육 수업 대기시간 수치는 실무자 자료와 추론이다(LOW). 페이싱 계산은 이 문서에서 직접 추정한 값이다.

> 범위: v2.0의 **새 기능만** 다룬다. 미션·이벤트 CRUD, 가중치, localStorage, JSON 내보내기/가져오기(Zod), 개인전/팀전 설정 화면, 큰 버튼 UI는 이미 있으므로 재조사하지 않았다. 다만 그 위에 올라가는 의존 관계는 아래에 정리했다.

## 장르 관행 요약 (근거)

| 관행 | 참고 게임 | 우리 게임에 주는 시사점 |
|------|-----------|-------------------------|
| 출발 칸은 **지나가거나 멈추면** 작은 고정 보너스를 준다 | Monopoly Junior(GO = $2, 멈춤/통과 모두), 부루마불(한 바퀴 돌면 월급) | 출발 보너스 = 별 +1을 기본값으로 둔다. "강제 이동(감옥행)은 출발을 지나도 보너스 없음" 규칙은 뒤로 N칸 이벤트에 그대로 적용한다 |
| 기본 칸이 판의 절반쯤, 이벤트 칸이 20~25%쯤 | Mario Party 1: 파란 칸 48%, 빨간 칸 7%, 해프닝 24% / Superstars: 파랑 40%, 빨강 11%, 이벤트 21%, 럭키 17% | 퀘스트 칸 약 70%, 이벤트 칸 약 25%, 출발 1칸. 퀘스트 칸이 기본 칸 역할을 한다 |
| **턴(라운드) 수로 게임 길이를 정한다**. 10~30턴, 5단위, 진행 중 1회 연장 가능 | Mario Party Superstars(10턴 약 30분, 30턴 약 90분) | 라운드 수를 핵심 설정으로 둔다. 진행 중 늘리기/줄이기와 "지금 끝내기"가 있어야 한다 |
| 마지막 몇 턴은 따로 알린다(Last Five Turns / Homestretch, 칸 효과 2배) | Mario Party 시리즈 | "마지막 라운드!" 배너는 필수로 넣는다. 별 2배는 선택 옵션(차별화)으로 둔다 |
| 끝나면 시상식을 한다. 보너스 별 3개, **동점이면 모두 받는다** | Mario Party Bonus Stars(미니게임왕·이벤트왕·이동왕) | 동점 공동 승리는 장르 관행과 맞다. 시상식은 따로 단계로 만들되 짧게 끝낸다 |
| 파산 1명이 생기면 게임이 끝나고 현금이 가장 많은 사람이 이긴다 | Monopoly Junior | **피해야 할 것.** 돈·파산·탈락은 아동 수업에 맞지 않는다(PROJECT.md Out of Scope와 같은 결론) |
| 상대 별을 빼앗거나 칸에서 별을 잃는다 | Mario Party(Boo, 빨간 칸, 결투) | **피해야 할 것.** 별은 늘기만 한다 |

**수업 맥락:** 45분 체육 수업에서 학생이 실제로 움직이는 시간은 약 17분이라는 추정이 있고, 체육 교수법은 대기시간 줄이기를 핵심 과제로 다룬다(LOW). 이 게임은 한 번에 한 명(한 팀)만 뛰는 구조라 **화면 연출이 길어지면 그만큼 아이들이 기다린다.** 그래서 페이싱은 화면 연출이 아니라 **아이가 줄넘기를 하는 시간**을 기준으로 잡아야 한다.

## 페이싱 계산 (설정 기본값의 근거)

한 턴의 예상 시간(추정):

| 단계 | 시간 | 비고 |
|------|------|------|
| 주사위 굴리기 + 이동 | 3~5초 | 주사위 약 1.2초 + 칸당 약 0.3초 × 1~6칸 |
| 퀘스트 카드 공개 | 1~2초 | |
| **아이가 미션 수행** | **15~40초** | 이 시간이 대부분이다. 앱이 줄일 수 없다 |
| 강사 판정 | 1~2초 | |
| 성공 연출 + 별 날아가기 | 2~3초 | 탭하면 넘길 수 있게 |
| 다음 차례로 넘기기 | 2~5초 | 줄 넘겨주기, 자리 이동 |
| **합계** | **약 30~60초** (평균 45초로 잡음) | |

라운드 수 기본값(1라운드 = 모든 참가자가 한 번씩):

| 참가자/팀 수 | 1라운드 시간 | 20분 수업 | 30분 수업 | 40분 수업 |
|--------------|--------------|-----------|-----------|-----------|
| 2 | 약 1.5분 | 12 | 18 | 25 |
| 4 | 약 3분 | 6 | 10 | 12 |
| 6 | 약 4.5분 | 4 | 6 | 8 |
| 8 | 약 6분 | 3 | 5 | 6 |

**결론:** 라운드 기본값을 하나로 고정하면 안 된다. 설정 화면에서 라운드 수를 고르면 **"예상 약 N분"**(참가자 수 × 라운드 × 45초)을 보여 주고, 8명이면 3~6라운드, 2명이면 10~20라운드 범위를 쉽게 고를 수 있게 한다. 이렇게 하면 시간 제한 타이머 없이도 수업 시간에 맞출 수 있다.

**보드 크기:** 주사위 1개(평균 3.5칸)를 쓰면 20칸 판은 약 6턴에 한 바퀴다. 3~6라운드 게임에서 출발 보너스가 1번 이상 나오려면 **16~24칸**이 맞다. 부루마불의 40칸은 주사위 2개 기준이라 그대로 쓰면 출발 보너스가 거의 나오지 않는다. 기본값은 20칸(모서리 4 + 변마다 4칸)으로 하고, 16/20/24 프리셋을 둔다.

## Feature Landscape

### Table Stakes (없으면 미완성으로 느껴지는 기능)

| Feature | Why Expected | Complexity | Notes / 기존 코드 의존 |
|---------|--------------|------------|------------------------|
| **사각 순환판 + 출발 랜드마크** | 블루마블식이라는 정체성. 출발 칸이 크고 다르게 보여야 "한 바퀴"가 읽힌다 | MEDIUM | 모서리 칸 4개는 다른 칸보다 크게. 출발 칸은 깃발/아치 같은 3D 랜드마크. 기존 `boardLayout.ts`는 직선 레이스용이므로 사각 루프 좌표로 다시 짜야 한다 |
| **진행 방향 표시 + 칸 간격 + 칸 번호** | 사용자가 v1 시안을 반려한 이유가 "어디로 가는지 모르겠다"였다(메모리: board-must-read-game-state) | LOW | 바닥 화살표(쉐브론), 칸 사이 틈, 작은 번호. 루프에서는 결승점 대신 **출발 칸**이 기준 랜드마크다 |
| **칸 종류를 도착 전에 읽을 수 있게** | 아이들이 "저기 걸리면 별 3개!"를 보면서 기대해야 주사위가 재미있다. Mario Party도 칸 색만 보고 결과를 안다 | MEDIUM | 퀘스트 칸은 **난이도 색 + 별 개수 표시**(쉬움 초록 ⭐1 / 보통 노랑 ⭐2 / 어려움 빨강·보라 ⭐3). 이벤트 칸은 **모양과 아이콘이 다르게**(앞 화살표, 뒤 화살표, 회전 화살표). 글자 없이 색과 아이콘만으로 구분 |
| **칸 난이도 → 미션 뽑기** | 칸에 표시한 별과 실제 보상이 같아야 한다 | MEDIUM | 퀘스트 칸은 난이도만 가진다. 도착하면 **그 난이도의 미션 풀에서** 뽑는다(같은 미션이 바로 반복되지 않게 섞은 덱 방식). 기존 `Mission.diff`(easy/normal/hard)를 그대로 쓴다. 어떤 난이도의 미션이 0개면 그 난이도 칸을 배치하지 않거나 시작 전에 안내한다(MISSION-07 확장) |
| **도착 예정 칸 미리 반짝이기** | 주사위가 나오면 "어디에 멈출까"를 아이들이 따라 세며 긴장감이 생긴다 | LOW | 기존 `moveHighlight.ts` 로직을 재사용할 수 있다. 이동 중 칸마다 "통통" 소리/빛 |
| **턴 흐름 FSM: 주사위 → 이동 → 칸 처리 → (퀘스트) 판정 → 별 → 다음** | 마일스톤 핵심 루프. v1은 "카드 → 판정 → 주사위" 순서라 반대다 | HIGH | 기존 `Phase` 유니온(`awaitingDraw → awaitingJudgement → awaitingRoll`)을 다시 짜야 한다. 대략 `awaitingRoll → moving → resolvingTile → awaitingJudgement → (retry?) → awarding → turnEnd → roundEnd/gameOver`. ANIM_DONE 게이트(`usePresentation.ts`)는 그대로 쓴다 |
| **강사 성공/실패 버튼** | v1과 같다. 판정은 강사가 한다 | LOW | 버튼은 아이용 버튼과 위치·색을 구분해 아이가 실수로 누르지 않게 한다 |
| **난이도별 별 보상 (⭐1/2/3)** | 마일스톤 규칙 | LOW | 엔진에 `stars` 필드 추가. 별은 줄어들지 않는다 |
| **성공 연출(큰 축하)** | 마일스톤 목표: 점프·회전, 컨페티, 별 버스트, 충격파, 큰 별 → 점수판 +1, 배너 | HIGH | **총 2~3초 안에 끝내고 탭하면 넘어가게 한다.** 별 3개 미션은 연출 규모를 키워 보상 차이가 느껴지게. 아래 Anti-Features의 "긴 연출" 참고 |
| **실패 처리: 짧고 다정하게** | 아이가 위축되면 안 된다 | LOW | 1초 이내 슬픈 표정 + "다음엔 할 수 있어!" 같은 격려. 빨간 X, 버저음, 별 깎기는 금지 |
| **실패 규칙 설정** | 마일스톤에 명시됨. 강사마다 수업 방식이 다르다 | MEDIUM | 선택지 2개: ① 별 없이 차례 넘김 ② **한 번 더 도전**(1회) 후 실패하면 넘김. 기본값은 ② 추천(아동 수업에서 재시도가 학습 효과가 크고, 1회로 제한해 시간은 지킨다). 재도전 상태는 FSM의 하위 상태로 둔다 |
| **출발 보너스 설정** | 블루마블·Monopoly Jr의 대표 규칙 | LOW | 끔 / +1 / +2 중 고르기, 기본값 +1. **멈추거나 지나갈 때 한 번.** 뒤로 이동해서 출발을 지날 때는 주지 않는다(Monopoly Jr 감옥 규칙과 같음) |
| **라운드 수 설정 + 예상 시간 표시** | 시간 타이머 없이 수업 시간을 맞추는 유일한 수단 | LOW | 위 페이싱 표. 범위 1~30, 기본값은 인원에 따라 자동 추천(예: 약 25분 목표) |
| **라운드 카운터 HUD** | 아이와 강사 모두 "언제 끝나?"를 계속 묻는다 | LOW | "라운드 3 / 5"를 점(●●●○○)으로 표시. 숫자를 못 읽는 아이도 알 수 있게 |
| **"마지막 라운드!" 알림** | Mario Party의 Last Five Turns/Homestretch처럼 긴장감을 만든다 | LOW | 마지막 라운드가 시작될 때 배너 1~2초 |
| **차례 표시 + 다음 차례 미리보기** | 체육 수업에서는 다음 아이가 미리 줄을 들고 준비해야 한다. 대기시간이 줄어든다 | LOW | 지금 차례: 큰 캐릭터 얼굴 + 이름. 그 옆에 "다음: ○○" 작게. 팀전이면 **팀 이름 + 지금 뛸 팀원 이름**을 크게(기존 `memberNames`/`memberTurnIndex` 재사용) |
| **별 점수판 + 순위** | 별 최다 승리 규칙이라 "누가 이기고 있나"가 계속 보여야 한다(메모리: board-must-read-game-state) | MEDIUM | 별 많은 순으로 정렬된 세로 띠. 캐릭터 얼굴 + ⭐숫자를 크게. **동점은 같은 등수**(1, 1, 3). 순위가 바뀌면 칸이 미끄러지는 애니메이션. 8명까지 한 화면에 들어가야 한다(iPhone 가로 포함) |
| **별 → 점수판으로 날아가기** | 보상과 점수의 연결이 눈에 보여야 한다 | MEDIUM | 성공 연출의 마지막 단계. 점수판 숫자가 "+1" 튀면서 올라간다 |
| **종료 시상식 + 공동 우승** | 별 최다 승리, 동점 공동 승리(마일스톤 규칙, Mario Party Bonus Star 동점 처리와 같다) | MEDIUM | 드럼롤 → 1위(공동 1위면 같이) 시상대 → 모두의 별 개수. **꼴찌 강조 없음.** 다시 하기 / 처음으로 버튼(LOOP-10 재사용) |
| **강사 "지금 끝내기"** | 수업 시간은 예측하기 어렵다. 라운드 도중에도 바로 시상식으로 갈 수 있어야 한다 | LOW | 기존 `EndReason`의 `'manual'`을 재사용. 확인창 필요 |
| **라운드 공정성** | 라운드 끝 = 모든 참가자가 같은 횟수만큼 뛴 상태 | LOW | "한 번 더"(extra) 추가 턴은 라운드 진행에 세지 않는다. 연속 "한 번 더"는 1회로 제한해 무한 반복을 막는다 |
| **이벤트 칸 효과 (앞/뒤 N칸, 한 번 더)** | 마일스톤에서 유지하기로 함 | MEDIUM | 루프에서는 위치를 `mod 보드길이`로 계산한다. **이벤트로 이동해 도착한 퀘스트 칸은 퀘스트를 실행하고, 이벤트 칸이면 다시 발동하지 않는다**(연쇄 방지). 아래 "결정 필요" 참고 |
| **보드 배치 = 가중치 기반 이벤트 + 난이도 분포** | EVENT-06(가중치 배치)이 v1에서 미완성이었다 | MEDIUM | 기존 `placement.ts`를 루프용으로 바꾼다. 출발 칸에는 아무것도 두지 않고, 이벤트 칸끼리 붙지 않게, 앞쪽 몇 칸에는 쉬운 퀘스트를 둔다 |
| **강사 설정 저장** | 매 수업 다시 고르면 귀찮다 | MEDIUM | 라운드, 실패 규칙, 출발 보너스, 보드 크기를 localStorage에 저장한다. **주의:** `ContentSchema.version`이 `z.literal(1)`이라 설정을 같은 스키마에 넣으면 기존 JSON 가져오기가 깨진다. 설정은 **별도 persist 슬라이스**로 두거나 마이그레이션과 함께 버전을 올려야 한다 |
| **잘못 누른 판정 되돌리기** | 강사가 바쁘게 진행하다 성공/실패를 잘못 누르는 일이 생긴다. 별이 틀리면 아이들이 바로 항의한다 | MEDIUM | 별 지급 직후 몇 초 동안 "되돌리기" 버튼을 보여 준다. 헤드리스 엔진이면 직전 상태 스냅샷 1개로 쉽게 만들 수 있다 |

### Differentiators (있으면 확실히 좋아지는 기능)

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **난이도별 연출 강도 차이** | 어려운 미션을 고른/걸린 아이가 더 크게 축하받는다. "어려운 것도 해 볼래" 동기가 생긴다 | LOW | ⭐1: 점프 + 컨페티 조금 / ⭐2: + 별 버스트 / ⭐3: + 충격파 링 + 화면 흔들림 + 배너. 길이는 셋 다 3초 이내 |
| **표정이 상황을 따라가는 치비 동물** | 마일스톤 핵심 아트. 아이 감정을 대신 표현한다 | HIGH (아트) | 기본, 두근(주사위·이동), 기쁨(성공), 슬픔(실패, 짧게), 놀람(이벤트), 우승(시상식). 다른 참가자 캐릭터도 응원 리액션을 하면 기다리는 아이들도 화면에 붙잡힌다 |
| **칭찬 배지 시상 (별과 별개)** | Mario Party 보너스 별을 아동용으로 바꾼 것. 별 순위는 그대로 두고 **모두가 무언가를 받게** 해서 하위권 아이도 기분 좋게 끝난다 | MEDIUM | "도전왕(어려운 미션 성공 최다)", "끈기왕(재도전 성공)", "여행왕(가장 많이 이동)" 등. 승패를 바꾸지 않는다(Mario Party와 다른 점) |
| **마지막 라운드 별 2배 (옵션)** | Mario Party의 마지막 5턴 규칙. 뒤처진 아이에게 역전 기회를 준다 | LOW | 설정에서 켜고 끄기, 기본은 끔. 어린 아이에게는 따라잡기 장치가 좋다는 근거가 있다(LOW) |
| **예상 시간 자동 추천** | 강사가 계산하지 않아도 된다 | LOW | 위 공식. "25분 수업" 프리셋 버튼 → 라운드 자동 설정 |
| **진행 중 라운드 늘리기/줄이기** | Mario Party Superstars가 진행 중 턴 수 변경을 허용한다. 수업이 일찍/늦게 끝날 때 유용하다 | LOW | 강사 메뉴에서. 이미 지나간 라운드보다 작게는 못 줄인다 |
| **다음 차례 "준비!" 알림** | 다음 아이가 줄을 미리 잡아서 대기시간이 줄어든다(체육 수업의 대기시간 문제) | LOW | 판정 직후 다음 아이 캐릭터가 손을 흔드는 1초 연출 |
| **팀전 "다 함께" 미션 칸 (옵션)** | 팀원 모두가 같이 뛰어 활동량이 늘어난다 | MEDIUM | 판정은 팀 단위 1번으로 단순하게. 게임 규칙은 그대로 두고 화면에 "팀 모두!"만 표시해도 된다 |
| **효과음** | 연출 효과의 절반은 소리다 | LOW~MEDIUM | v1에서 AUDIO-01로 미뤄 둔 기능. 성공·이동·주사위 소리만이라도 있으면 축하 체감이 크게 오른다. 음소거 토글은 꼭 넣는다(수업 환경) |

### Anti-Features (그럴듯하지만 문제가 되는 기능)

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| **돈·땅 구매·통행료·건물** | 블루마블 하면 떠오르는 것 | 계산과 읽기 부담이 크다. 미션 수행보다 경제 판단이 승패를 가른다. 이미 Out of Scope | 보상은 별 하나 |
| **별 잃기·별 뺏기·함정으로 별 감소** | Mario Party식 반전 재미 | 아이가 실제로 줄넘기를 해서 번 별을 빼앗기면 운동 노력이 무의미해진다. 울음과 항의가 생긴다 | 함정은 "뒤로 N칸"까지만. 별은 줄지 않는다 |
| **탈락/파산/0점 강조** | Monopoly Jr처럼 게임 끝 조건을 만들려고 | 탈락한 아이는 남은 시간 동안 할 일이 없다. 수업 참여 원칙에 어긋난다 | 라운드 수로 끝낸다. 모두 끝까지 참여 |
| **길고 못 넘기는 연출(5초 이상)** | 화려할수록 좋아 보인다 | 한 턴 45초 중 연출 10초면 8명 × 5라운드에서 약 7분이 사라진다. 다음 아이가 기다린다 | 성공 연출 3초 이내, 탭으로 넘기기, 이동은 칸당 약 0.3초 |
| **시간 제한 타이머(게임 전체)** | v1에 `timeLimitMs`가 있었다 | 마일스톤에서 "라운드 수만, 타이머 없음"으로 정했다. 타이머로 끝나면 라운드 중간에 끝나 차례를 못 받은 아이가 생긴다 | 라운드 수 + 예상 시간 표시 + "지금 끝내기". 기존 `timeLimitMs`와 `TurnHud` 시계는 제거한다 |
| **미니게임·아이템·상점·갈림길** | Mario Party처럼 풍부하게 | 화면 안에서 결정할 게 늘어날수록 줄넘기 시간이 줄어든다. 갈림길은 아이가 고민하느라 시간이 든다 | 화면은 주사위와 결과만. 활동은 줄넘기 하나 |
| **주사위 2개 합산·더블** | 부루마블 원작 규칙 | 덧셈 부담이 있고, 더블 추가 턴은 라운드 공정성을 깨뜨린다 | 주사위 1개, 판 16~24칸 |
| **글이 많은 이벤트 카드(황금열쇠식)** | 블루마블 느낌 | 글을 못 읽는 아이가 많다. 강사가 매번 읽어 줘야 한다 | 아이콘 + 숫자("➡️ 3"), 짧은 이름 한 단어 |
| **칸 하나하나 직접 편집하는 보드 에디터** | 강사 커스터마이징 확장 | 편집 화면이 크게 늘어나는 데 비해 효과는 작다. 가중치 + 비율로 충분하다 | 보드 크기 프리셋 + 이벤트 가중치(기존) + 난이도 비율(선택) |
| **"꼴찌" 표시·순위 낮은 순 발표** | 순위를 정확히 보여 주려고 | 아동 수업에서는 망신을 주는 장치가 된다 | 시상대는 1위(공동 포함)만 강조하고 나머지는 별 개수와 칭찬 배지로 |
| **판정 자동화·아이가 직접 성공 누르기** | 강사 부담을 줄이려고 | 이미 Out of Scope(센서). 아이에게 판정을 맡기면 다들 성공을 누른다 | 강사 전용 버튼, 위치·색 구분 |
| **결과 기록·통계·반 전체 랭킹 저장** | 동기 부여 | 아동 비교 데이터가 쌓이고, 저장 구조가 복잡해진다(QOL-03 이미 연기) | 이번 게임 시상식에서 끝낸다 |

### Dependency Notes

- **FSM 재설계가 모든 것의 뿌리다.** v1 엔진은 "카드 → 판정 → 주사위 → 결승" 순서다. v2는 순서가 반대이고, 결승 대신 라운드로 끝난다. 엔진을 먼저 헤드리스로 다시 짜고 테스트로 고정해야 3D 화면과 연출을 병렬로 만들 수 있다. 엔진이 React/시간 의존 없이 순수하다는 v1 규칙은 그대로 지킨다.
- **칸 난이도가 미션 풀에 의존한다.** 어떤 난이도의 미션이 0개일 수 있다(강사가 지울 수 있음). 시작 차단 검사를 "미션 1개 이상"에서 "보드에 놓인 난이도마다 1개 이상, 없으면 그 난이도 칸 안 놓기"로 넓혀야 한다.
- **설정 저장은 스키마 버전과 충돌한다.** `ContentSchema.version`이 `z.literal(1)`이라 설정 필드를 콘텐츠 스키마에 넣고 버전을 올리면 v1 JSON 가져오기가 거부된다. 설정은 별도 저장 키로 두는 것을 추천한다(내보내기 파일에 넣을지는 별도로 정한다).
- **연출은 ANIM_DONE 게이트에 의존한다.** 기존 `usePresentation.ts` 패턴(연출이 끝나야 엔진이 다음 단계로)을 그대로 쓰고, "탭해서 넘기기"는 게이트를 바로 여는 것으로 구현한다. 엔진이 연출 시간을 알 필요가 없다.
- **팀전은 기존 모델 그대로다.** 팀 = 말 1개 + 팀원 순환(`memberTurnIndex`). 별은 팀 단위로 쌓는다. 라운드 = 팀마다 1턴이다.
- **타이머 제거.** v1 `GameConfig.timeLimitMs`, `PlayView`의 시계 effect, `TurnHud` 시계는 v2 규칙과 맞지 않으므로 지운다. `EndReason`은 `'rounds-complete' | 'manual'`로 바꾼다.

## 결정 필요 (로드맵·요구사항 단계에서 확정할 것)

| 질문 | 추천 | 이유 |
|------|------|------|
| 이벤트로 이동해 도착한 칸이 퀘스트 칸이면 퀘스트를 하나? | **한다.** 단 이벤트 칸이면 다시 발동하지 않는다 | 줄넘기 기회가 많을수록 수업 목적에 맞다. 연쇄를 막으면 무한 루프가 없다 |
| "한 번 더"는 주사위만 다시인가, 퀘스트 포함인가? | 주사위부터 턴 전체를 1번 더. 라운드 수에는 세지 않는다. 연속은 최대 1회 | 아이 입장에서 단순하다. 공정성은 상한으로 지킨다 |
| 칸 난이도를 보드 시작 때 고정하나, 매 게임 섞나? | 게임 시작 때 가중치로 배치하고 게임 중에는 고정 | 아이들이 칸을 보고 기대할 수 있어야 한다(도착 전 가독성) |
| 퀘스트를 칸에 미리 정해 두나(미션 이름 노출), 난이도만 정하나? | **난이도만.** 미션은 도착할 때 그 난이도 덱에서 뽑는다 | 3D 칸에 글자를 넣으면 읽히지 않는다. 뽑는 순간이 작은 이벤트가 된다 |
| 출발 칸에 정확히 멈추면 보너스 2배? | 아니다. 멈추든 지나가든 한 번 | 규칙을 하나 줄인다 |
| 실패 기본값 | 1회 재도전 | 학습 효과와 시간을 둘 다 지킨다. 강사가 "재도전 없음"으로 바꿀 수 있다 |
| 보너스 별 레이블('보너스'/'함정') | 이벤트 칸 색(좋은 이벤트 하늘색, 함정 회색-보라)에만 쓴다 | 기존 `EventLabel` 재사용, 스키마 변경 없음 |

## MVP Definition

### Launch With (v2.0)

- [ ] 엔진 FSM 재설계(주사위 → 이동 → 칸 처리 → 판정 → 별, 라운드 종료) — 모든 기능의 바탕
- [ ] 사각 루프 보드 레이아웃 + 출발 랜드마크 + 방향 화살표 + 칸 간격·번호
- [ ] 퀘스트 칸 난이도 색·별 표시, 이벤트 칸 아이콘·모양 구분
- [ ] 가중치 기반 보드 배치(출발 / 난이도 퀘스트 / 이벤트), 연쇄 방지
- [ ] 난이도별 별 지급(1/2/3), 출발 보너스(통과/정지, 뒤로 이동 제외)
- [ ] 강사 설정: 라운드 수(예상 시간 표시), 실패 규칙(없음/1회 재도전), 출발 보너스(끔/+1/+2), 보드 크기(16/20/24) — 별도 저장
- [ ] 차례 표시 + 다음 차례 미리보기 + 팀원 이름
- [ ] 별 점수판(정렬, 동점 같은 등수) + 라운드 카운터 + 마지막 라운드 배너
- [ ] 치비 동물 캐릭터 + 기본/두근/기쁨/슬픔/우승 표정
- [ ] 성공 연출(3초 이내, 탭으로 넘김, 별이 점수판으로 날아감), 짧은 실패 연출
- [ ] 종료 시상식(공동 우승, 꼴찌 강조 없음) + 다시 하기/처음으로
- [ ] 강사 메뉴: 지금 끝내기, 판정 되돌리기

### Add After Validation (v2.x)

- [ ] 난이도별 연출 강도 차이 — 기본 연출이 수업에서 검증된 뒤
- [ ] 칭찬 배지 시상 — 하위권 아이가 시상식에서 시무룩하다는 피드백이 나오면
- [ ] 효과음 + 음소거(AUDIO-01/02) — 연출이 조용하게 느껴진다는 피드백이 나오면. 사실상 1순위 후보
- [ ] 진행 중 라운드 늘리기/줄이기, "25분 수업" 프리셋
- [ ] 마지막 라운드 별 2배 옵션

### Future Consideration (v3+)

- [ ] 팀전 "다 함께" 미션 칸 — 판정 규칙이 달라 별도 설계가 필요하다
- [ ] 난이도 비율 직접 설정 — 기본 배치로 부족하다는 강사 요청이 생기면
- [ ] 게임 도중 저장/이어하기(QOL-01) — 수업이 끊기는 일이 잦다면
