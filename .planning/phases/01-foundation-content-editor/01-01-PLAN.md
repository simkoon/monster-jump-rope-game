## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → app (rehydrate) | Persisted JSON is untrusted on load — it may be corrupt, partial, hand-edited, or from an older/newer schema version |
| npm registry → build | Third-party packages enter the trusted build/runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / DoS | store.ts rehydrate (`merge`) | low | mitigate | `merge` runs `ContentSchema.safeParse` on the persisted payload; on any failure it returns the seed/current state instead of adopting corrupt data (read-guard). App never crashes on bad storage. |
| T-01-02 | DoS (local) | store.ts persist write | low | accept | localStorage quota overflow on save is caught by `persist`'s storage adapter; in-memory state is preserved. For a dozens-of-records teacher library this is a non-issue; no extra handling this phase. |
| T-01-SC | Tampering (supply chain) | package.json installs (scaffold) | high | mitigate | Install ONLY the exact pinned versions from RESEARCH §Package Legitimacy Audit (all verdicts Approved; no [SLOP]; every [SUS] is a `too-new` recency false-positive on a canonical 40M-240M-download package with a verified official repo). Exact-version pins + committed lockfile prevent a compromised newer patch. Dev-only test deps (vitest, @testing-library/*, jsdom) are canonical packages from official repos. No blocking human-verify checkpoint required (researcher cleared the audit). |
</threat_model>
