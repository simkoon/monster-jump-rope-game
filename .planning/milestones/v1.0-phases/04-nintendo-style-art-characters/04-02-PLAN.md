# 04-02 PLAN — Kenney character pose/expression switching

## Goal
Make the existing Kenney boy/girl tokens react to game state without changing engine/store rules: idle rope pose while waiting, cheer on successful mission judgement, hurt on failed mission judgement, and walk frames during token movement.

## Scope
- Add a presentation-only token pose contract between `PlayView` and `BoardScene`.
- Keep `useGameStore`, engine transitions, RNG, and turn FSM behavior unchanged.
- Use already-imported CC0 files under `public/assets/cc0/kenney/toon-characters/`.
- Preserve Phase 3.1 board readability and Phase 4-01 candy visual treatment.

## Tasks
1. Add pose model in `BoardScene`.
   - Poses: `rope`, `cheer`, `hurt`, `walk`.
   - Map to `boy/girl-{pose}.png`; walk cycles through `walk0..walk3`.
   - Default non-active tokens remain rope.
2. Wire PlayView reactions.
   - Success judgement: briefly show active token `cheer`, then transition to `awaitingRoll`.
   - Failure judgement: briefly show active token `hurt`, then advance turn.
   - Token hop: active token uses walk frame cycle during `seq === 'token'`.
   - Turn resolved: active token may briefly stay cheer after arrival.
3. Update tests.
   - Scene test asserts `cheer`, `hurt`, and `walk` asset paths.
   - HUD test asserts success/failure reactions call store judgement after the short reaction delay.
4. Verify.
   - `npm run build`
   - `npm test`
   - Browser smoke: success → dice → walk/dice flow and failure → hurt/next-turn flow.

## Out of Scope
- New art asset downloads.
- New game rules or result scoring changes.
- Physical tablet/iPhone UAT.
