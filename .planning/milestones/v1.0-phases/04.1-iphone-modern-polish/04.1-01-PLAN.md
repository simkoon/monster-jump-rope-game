# 04.1-01 PLAN — iPhone-first modern polish

## Goal
Fix iPhone layout breakage and add a cleaner modern shell: Apple/Toss-like for setup/editor surfaces, while preserving the Nintendo-like game stage.

## Must-haves
- When an active game is running, the app enters a true fullscreen playing shell on mobile: no global header/view switch stealing viewport height.
- Setup/editor/result surfaces feel clean, airy, modern, and less toy-heavy: softer background, subtle shadows, rounded cards, smaller chrome.
- PlayView remains colorful/game-like and keeps Phase 3.1 board readability.
- No engine/store rule changes.
- `npm run build` and `npm test` pass.
- Browser smoke checks public/local iPhone-sized behavior as far as tools allow.

## Tasks
1. App state shell
   - Read `App.tsx`, `GameApp.tsx`, `useGameStore`.
   - Add `app--playing` class when `view === 'game'` and an active game exists.
   - Keep setup and editor navigation reachable before a game starts.
2. Modern shell CSS
   - Add Apple/Toss-like neutral tokens: calmer background, softer cards, cleaner buttons.
   - Tighten header/view switch on narrow screens.
3. iPhone game CSS
   - In `.app--playing`, hide app header/view switch and make game main/stage full viewport.
   - Compact board, HUD, controls, and rank strip for 390px-ish portrait widths.
   - Ensure bottom controls do not overlap board/finish.
4. Tests
   - Add shell test for `app--playing` class after game start.
5. Verification
   - Build/test.
   - Browser smoke: setup visible, start game, board/buttons/rank readable, one turn works, no broken images.

## Out of scope
- New assets.
- New game mechanics.
- Physical-device Safari UAT; note if not performed.
