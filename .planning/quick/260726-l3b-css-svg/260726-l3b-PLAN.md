<design_constraints>
전 태스크에 공통으로 적용되는 하드 룰. 위반 시 태스크는 완료가 아니다.

1. **에셋 금지.** 이미지 파일, 데이터 URI 이미지, 외부 SVG 파일, 아이콘 라이브러리, 새 npm 패키지를 도입하지 않는다. 일러스트는 CSS `linear-gradient`/`radial-gradient`/`conic-gradient` 레이어와 손으로 작성한 인라인 `<svg>` JSX만 사용한다. 이모지는 기존 코드베이스가 이미 어포던스로 쓰는 수준(예: Header/App 토글)에서만 허용한다.
2. **R3F 금지.** 로비에는 `<Canvas>`를 넣지 않는다. 3D는 PlayView의 기존 씬에서만 쓴다(로비 첫 화면 비용을 0으로 유지).
3. **팔레트 포크 금지.** 새 색상 값(hex/hsl 리터럴)을 만들지 않는다. `--sky --sky-deep --sun --sun-deep --coral --pink --grass --grape --panel --panel-2 --ink --ink-soft --line --shadow --shadow-sm --gloss --radius --radius-sm`와 `--tap --tap-sm --game-display --game-heading --game-body --game-caption`를 그대로 쓴다. 반투명 셰이딩이 필요하면 `color-mix(in srgb, var(--토큰) N%, transparent)` 또는 `rgba(255,255,255,...)`/`rgba(0,0,0,...)` 광택 레이어만 사용한다(기존 `--gloss` 관례와 동일).
4. **다크 모드.** 본문 텍스트는 항상 `var(--panel)`/`var(--panel-2)` 배경 위에 `var(--ink)`/`var(--ink-soft)`로 올린다. 그려진 하늘·들판 위에 직접 얹는 텍스트는 만들지 않는다(색조 토큰은 다크 모드에서 바뀌지 않으므로 대비가 깨진다). 히어로 로고는 예외이며, CSS 스트로크+그림자로 자체 대비를 확보한다.
5. **접근성.** 장식 아트를 감싸는 모든 요소는 `aria-hidden="true"`, 모든 `<svg>`는 `aria-hidden="true" focusable="false"`. 조작 요소는 전부 실제 `<button type="button">`이고 접근 가능한 이름을 가진다. 포커스 링은 기존 관례(`:focus-visible { outline: 3px solid var(--sky); outline-offset: 2px; }`)를 따른다.
6. **모션.** 새 애니메이션은 `prefers-reduced-motion: reduce`에서 반드시 정지해야 한다. index.css가 전역으로 `animation:none!important`를 걸어두므로 애니메이션은 `@keyframes` + `animation` 속성으로만 구현하고(인라인 style의 `transform` 루프나 JS 타이머로 움직이지 않는다), 애니메이션이 멈춘 상태에서도 레이아웃이 정상으로 보여야 한다.
7. **가짜 기능 금지.** HP, 에너지, 코인, 젬, 레벨, Lv., XP, 경험치, 랭킹, 상점, 배지, 메일, 출석, 보상 같은 문구·수치·슬롯을 만들지 않는다. 실제 기능이 없는 레퍼런스 슬롯(좌상단 플레이어 카드, 우측 다음 레벨 보상 패널, 우상단 메일/설정 아이콘 버튼)은 흉내 내지 말고 **삭제**한다.
8. **쿼리 충돌 방지(기존 테스트 보호).** 로비 렌더 트리에서 텍스트가 정확히 `파워점핑`인 요소는 `<h1>` 하나뿐이어야 하고(문자별 span 분해 금지 — 3D 느낌은 CSS `-webkit-text-stroke`/`paint-order`/다중 `text-shadow`로만 낸다), 이름에 `시작`이 포함된 버튼도 CTA 하나뿐이어야 한다. 그래서 하단 내비 라벨은 `게임 / 미션 / 이벤트`를 쓴다(`게임 시작` 금지). 이 두 규칙을 지키면 기존 `src/App.test.tsx`의 첫 마운트 테스트가 그대로 통과한다.
</design_constraints>
