## 0. 한 줄 요약

게임은 **이미 완성되어 플레이 가능**하다. 다만 3D는 전부 절차적 도형(캡슐+구=말, 둥근 상자=주사위/타일)이고 아이콘은 이모지다. 이 문서는 그 플레이스홀더를 대체할 **에셋의 정확한 규격**을 정의한다.

## 2. 절대 제약 (협상 불가)

1. **IP 금지** — 실존 브랜드·상표·캐릭터·저작권 자산 일절 사용 불가. 오리지널 창작물 또는 **CC0** 소스만. 특정 게임사 캐릭터를 연상시키는 디자인도 불가(스타일 참조는 가능, 형태 모방은 불가).
2. **웹 즉시 실행** — 다운로드/설치 체감이 없어야 한다. §7 용량 예산 준수.
3. **모든 텍스트는 한국어**, 아동이 읽을 수 있는 수준. 로고 외 텍스트를 이미지에 굽지 말 것(다국어/편집 불가해짐).
4. **색상만으로 의미를 전달하지 말 것** — 접근성. 모든 상태는 색 + 형태/아이콘/라벨 조합으로 구분.
5. **팔레트 고정** — §3 표의 hex를 그대로 사용. 새 색상 도입은 사전 합의 필요.

## 3. 공통 규격

### 3.1 색상 팔레트 (단일 소스: `src/styles/index.css`)

에셋의 베이스 컬러는 아래 값에서 선택한다. 텍스처에 하드코딩할 때도 동일 hex 사용.

| 토큰 | Hex | 용도 |
|------|-----|------|
| `--sky` / `--sky-deep` | `#22B0F2` / `#1183D6` | 주 브랜드색, 활성 강조, 기본 버튼 |
| `--sun` / `--sun-deep` | `#FFCB2E` / `#FF9F1C` | 결승/보상/하이라이트 |
| `--coral` | `#FF5C7A` | 실패, 함정, 뒤로 |
| `--pink` | `#FF80B5` | 여자 캐릭터 계열, 액센트 |
| `--grass` | `#25D6A0` | 성공, 앞으로, 쉬움 |
| `--grape` | `#9A7DFF` | 보너스, 한 번 더 |
| `--ink` / `--ink-soft` | `#173A57` / `#6488A5` | 라인·눈동자·텍스트(순검정 금지) |
| 라이트 배경 | `#E7F5FF` → `#FFF3E6` | 하늘색→크림 그라디언트 |
| 다크 배경 | `#0C1A2B` → `#13233A` | 다크 모드 |

**다크 모드가 존재한다.** 3D 씬 clear color는 라이트 `#E7F5FF` / 다크 `#0C1A2B`로 바뀐다. 캐릭터·타일은 두 배경 모두에서 대비가 확보되어야 한다(특히 흰색 계열 주의).

`#22B0F2` → `#FF5C7A` → `#25D6A0` → `#FFCB2E` → `#9A7DFF` → `#FF80B5`

### 3.2 3D 좌표계·단위 (glTF 저작 규칙)

| 항목 | 값 |
|------|-----|
| 포맷 | **`.glb`** (glTF 2.0 binary), Draco 압축 |
| 축 | Y-up, 오른손 좌표계 (Blender glTF 익스포터 기본) |
| 단위 | 1 unit = 보드 타일 1칸 폭 ≈ **0.94** |
| 원점(origin) | **발밑 중앙 (0, 0, 0)** — 코드가 `position.y = 0`에 놓고 hop 시 y만 올린다 |
| 정면 | **+Z 방향** |
| 스케일 | 익스포트 전 **transform apply** (scale 1,1,1) |
| 머티리얼 | glTF PBR metallic-roughness. 토이 플라스틱 룩: `roughness 0.22~0.35`, `metalness ≤ 0.12` |
| 텍스처 | PNG 또는 KTX2. **512×512 이하**, POT |

씬 실측치 (참고용, 이 안에 들어와야 함):

- 보드 타일: `0.94 × 0.30 × 0.94`, 타일 간격 `GAP = 1.15`, 6칸마다 뱀형(boustrophedon)으로 꺾임
- 현재 말 실루엣: 총 높이 약 `0.94`, 최대 폭 약 `0.48`
- 주사위: 한 변 `0.9`, 위치 `[-1.6, 1.3, 1.5]` 공중
- 카메라: 고정 아이소메트릭 `position [8, 11, 12]`, `fov 40`, **자유 회전 없음** — 즉 캐릭터는 **위에서 비스듬히 내려다보는 각도**에서 가장 잘 보여야 한다. 정수리와 얼굴이 동시에 보이는 각도이므로 **머리를 크게(2~2.5등신)**, 얼굴을 약간 위로 향하게 설계할 것.
- 조명: 반구광(0.75) + 방향광 `[6,12,6]` 웜톤(1.15) + 쿨 림라이트 `[-6,6,-4]`. AO/그림자를 텍스처에 굽지 말 것(런타임 ContactShadows가 이미 있음).

### A. 3D 캐릭터 — `ART-02`, `ART-03` (P0)

플레이스홀더 캡슐 말을 대체한다. 게임에서 가장 눈에 띄는 에셋.

| ID | 파일 | 우선순위 |
|----|------|----------|
| `CH-01` | `public/models/character-boy.glb` | **P0** |
| `CH-02` | `public/models/character-girl.glb` | **P0** |

**요구사항**

- 남자/여자 각 1종. 아동 체형, **2~2.5등신 치비 비례**(머리 크게).
- **줄넘기 줄을 손에 들고 있어야 한다** (ART-02 명시). 줄은 캐릭터 메쉬에 포함, 별도 물리 없음. 늘어진 U자 형태 권장 — 얇은 튜브로 폴리곤 절약.
- 실루엣이 단순하고 둥글 것. 24px 썸네일 수준으로 축소되어도 남/여 구분이 가능해야 한다(헤어 실루엣으로 구분, 색상 의존 금지).
- 밑변 지름 ≤ **0.8 unit**, 총 높이 **0.95 ~ 1.10 unit** (타일보다 크면 겹쳐 보임).
- **의상은 색상 교체 가능한 별도 머티리얼 슬롯**으로 분리할 것. 참가자 최대 6명이 §3.1의 6색으로 구분되므로, 코드가 해당 머티리얼의 `color`만 바꿔 6가지 변형을 만든다. 피부·머리카락·눈은 별도 슬롯으로 두어 색 교체 영향을 받지 않게 한다.
  - 머티리얼 이름 고정: `Skin`, `Hair`, `Outfit`(← 이 슬롯만 코드가 tint), `Rope`, `Face`
- 폴리곤 예산: **≤ 4,000 tris / 캐릭터** (줄넘기 줄 포함)
- 텍스처: 512×512 베이스컬러 1장 이내 (또는 텍스처 없이 버텍스 컬러/머티리얼 색상만 — 더 선호)

### B. 표정 — `ART-03` (P0)

성공/실패/이동에 반응하는 표정. **블렌드셰이프가 아니라 텍스처 스왑 방식**으로 요청한다(로드맵 04-02 결정 사항, 비용·성능 이점).

| ID | 파일 | 우선순위 |
|----|------|----------|
| `CH-03` | `public/textures/face-atlas.png` | **P0** |

**계약 (코드가 이 규칙에 의존한다)**

- **512×512 단일 PNG, 2×2 그리드**. 각 셀 256×256.
- 셀 배치 **고정** (코드가 `texture.offset`을 계산함):

  | | 좌 (u=0) | 우 (u=0.5) |
  |---|---|---|
  | **상 (v=0.5)** | `idle` — 평상시 미소 | `success` — 활짝 웃음 ^^ |
  | **하 (v=0)** | `move` — 신난 표정, 입 벌림 | `fail` — 시무룩 (눈물/화남 아님) |

- 캐릭터 메쉬의 얼굴 면 UV는 **좌상단 셀(idle) 영역에 매핑**된 상태로 저작할 것. 런타임에 offset만 이동시킨다.
- 배경 투명, 눈·입만. 선 색은 `#173A57`(순검정 금지).
- 남/여가 같은 아틀라스를 공유할 수 있으면 최선. 불가하면 `face-atlas-boy.png` / `face-atlas-girl.png`로 분리하되 그리드 규칙은 동일하게 유지.
- **`fail` 표정은 절대 울거나 겁먹은 표정이 아니어야 한다** — 아동 대상이므로 "아쉽다, 다음엔 되겠지" 수준의 귀여운 시무룩.

## 6. 수용 기준 (체크리스트)

제출물은 아래를 모두 만족해야 승인된다.

- [ ] `.glb`가 Three.js `0.185.1` / drei `useGLTF`로 오류 없이 로드된다
- [ ] 캐릭터 원점이 발밑이고, `position.y = 0`에 놓았을 때 타일 위에 정확히 선다
- [ ] 캐릭터 높이가 0.95~1.10 unit, 밑변 지름 ≤ 0.8 unit
- [ ] `Outfit` 머티리얼 색상만 바꿔 6가지 참가자 색 변형이 만들어진다 (피부/머리/눈 불변)
- [ ] `face-atlas.png`가 2×2 고정 배치이고, UV offset 이동만으로 4표정이 전환된다
- [ ] 캐릭터에 줄넘기 줄이 포함되어 있다 (ART-02)
- [ ] 고정 아이소메트릭 카메라(`[8,11,12]`, fov 40)에서 얼굴과 표정이 명확히 읽힌다
- [ ] 라이트(`#E7F5FF`)·다크(`#0C1A2B`) 배경 모두에서 대비가 확보된다
- [ ] SVG 아이콘이 24px에서 식별 가능하고, 색상을 CSS로 주입할 수 있다
- [ ] 로고가 120px 폭에서 판독된다
- [ ] §7 용량·폴리곤 예산 내
- [ ] AO/그림자가 텍스처에 구워져 있지 않다
- [ ] 실존 브랜드/캐릭터를 사용하거나 연상시키지 않는다 (§2-1)
- [ ] `ASSET-MANIFEST.md`에 모든 외부 소스의 라이선스가 명시되어 있다

## 7. 성능 예산

태블릿 1대 운영 + 설치 없는 즉시 실행이 제품 제약이다.

| 항목 | 예산 |
|------|------|
| 캐릭터 1종 | ≤ 4,000 tris, ≤ 400 KB (Draco 후) |
| 결승 게이트 | ≤ 1,500 tris |
| 소품 전체 | ≤ 3,000 tris |
| 텍스처 1장 | ≤ 512×512 |
| 아이콘 1개 | ≤ 4 KB (SVG) |
| **추가 에셋 총합 (초기 로드)** | **≤ 2.5 MB** |
| 씬 전체 드로우콜 증가 | ≤ +20 (보드 타일은 인스턴싱 1콜 유지) |

현재 보드는 타일 전체가 **드로우콜 1개**(instancedMesh)다. 이 구조를 깨는 제안(타일별 개별 메쉬 등)은 사전 협의 필요.

## 8. 구현 측 대응 (참고 — 디자인 담당 작업 아님)

에셋 수령 후 구현 에이전트가 처리할 항목:

- `public/` 생성, `useGLTF` + `<Suspense>` 로더, preload
- `Token.tsx`의 캡슐/구를 `<primitive>` 캐릭터로 교체, `character: 'boy' | 'girl'` 필드로 분기 ([types.ts:18](src/engine/types.ts#L18))
- 게임 phase → 표정 매핑: `awaitingJudgement` → idle, 성공 판정 → success, 실패 → fail, hop 중 → move
- `Outfit` 머티리얼 인스턴스 clone + tint (공유 머티리얼 색상 오염 방지)
- glTF-Transform으로 Draco/텍스처 최적화 재검증
- 언마운트 시 dispose (현행 누수 방지 패턴 유지)

## 9. 미확정 — 회신 요망

제작 착수 전 아래를 확정해 주기 바란다.

1. **표정 방식**: 텍스처 스왑(§4-B) 확정인가? 아니면 블렌드셰이프(morph target)를 선호하는가? → 텍스처 스왑을 강하게 권장(성능·제작비).
2. **캐릭터 색상 변형**: `Outfit` 슬롯 tint 방식으로 6색을 만드는 것이 캐릭터 디자인상 자연스러운가? (예: 상의만 색이 바뀌는 구조)
3. **남/여 구분**: 헤어 실루엣만으로 구분 가능한가? 색상(파랑/분홍) 의존은 접근성상 피하고 싶다.
4. **미션 카테고리 아이콘**: 강사가 카테고리를 자유 생성하므로 고정 아이콘 세트를 만들 수 없다. 기본 카테고리 3~4종에만 아이콘을 붙일지 결정 필요.
5. **사운드(§4-H)**: 범위에 포함하는가? 포함 시 howler.js 설치가 선행되어야 한다.
6. **로고 폰트**: 상용 폰트 사용 여부와 라이선스 범위.
7. **납품 일정**: P0 항목(캐릭터 2종 + 표정 아틀라스 + 로고 + 아이콘 10종)의 예상 소요.
